# W2D: cross_core rules extension, build, size, compute and test record

Status 2026-10-14: **proved on LiteSVM; the drawn ending, referral, minimum raise and pushed refunds also ran on a local `solana-test-validator`; devnet proof pending funding (HUMAN_TASKS H27).** Nothing was deployed. Not audited.

## What was built

The `cross_core` program gained the rules extension of ADR-0450 to ADR-0462: an extension tail on `Cross` and `Order` written once by `set_rules` in the creating slot, print guards, a hard-to-game ending with a block-hash draw, identity limits and allocation classes with a lottery, locks and issuer neutrality (insiders, bond, arbiter), halt states and a lender print feed, recurring series, pushed refunds, a referral share, an oracle median, and a scaled-UI multiplier guard. A cross made by the deployed program has no tail and behaves as before; the upgrade-compatibility test settles one with the new binary.

Per-row outcomes are in the `W2D-<id>.md` files of the rows (B14, B5, B8, B9, B12, B13, VM7, W8, W11, B1, W4, Y1, W12, C1, Z3, X1, V4).

## Defect found while proving it on a real cluster

`create_cross` plus `set_rules` in one transaction was 1,251 bytes (limit 1,232) because `set_rules` carried its two lists padded with zeros (320 bytes). LiteSVM does not enforce the limit, so the 112 tests did not catch it. `set_rules` now takes `CompactRules` (the lists unpadded; the program pads them). `rules-tx-size.test.ts` pins the sizes (3 tests). A cross with eight insiders, two extra feeds and a bond together with a three-step schedule can still exceed one legacy transaction and would need an address lookup table: NOT VERIFIED either way.

## What a deploy changes

- Accounts: additive. Existing `Cross`, `Order`, `Protocol` and all other accounts keep deserializing; new crosses are allocated larger (the tail). New PDAs: applicant, class book, lock vault, lockup, halt state, print feed, arbiter registry, challenge, series. `Protocol` needs `set_arbiter` (H28) before bonded crosses.
- Clients: `packages/cross-core-client` regenerated; `getSetRulesInstruction` takes the rules flattened (spread `completeRules(...)`); a series stores the padded form (`paddedRules`). The three IDL copies (`packages/cross-core-client/idl`, `idls`, `crates/opening-cross-cpi/idls`) are identical.
- Indexer, API, web, mobile, backtester: new `NoPrintReason` values (`FloatTooLow` through `OracleDisagreement`) and new events must be decoded; code that switches on the reason needs the new cases. The SDK does not yet carry the rules builders (they live in `tests/core/src/rules-world.ts` and `tests/devnet/src/w2d-core-proof.ts`).
- Not wired: `coarseIndicative` is not applied by the API or apps.
