# W5-1D: indexer projections for the DAO and tranche a cross opens without a pool, the treasury movement read model, and two MCP drafts

Date: 2026-10-16. ADR-0930. Rows X3, B4 and F5 (the read model F5 needs). Nothing here ran against a cluster: `cross_settle` batch 2 is not deployed (H27), so every result below is from PGlite (Postgres compiled to WebAssembly, running the indexer's own migrations) with event bytes produced by the generated client encoders.

What the 20 indexer tests prove: both events decode with every field (including a `qPrice` above 2^64); look-alike bytes from another program and bytes written during a CPI are ignored; both rows project, `settle_events` attributes both events to the cross; a failed transaction and a repeated signature change nothing; one cross holds a pool venue, two DAOs and two tranches without any displacing another, and a hostile cross string is only data. For F5: each of the nine events becomes the movement the test spells out (kind, direction, asset, amount, counterparty, reference, `team_outflow`); a vote, a NAV-window proposal, a zero-amount milestone and an unattributable event write none; filters by treasury, kind, direction, asset, team outflow, counterparty, minimum amount and slot; keyset paging with no gaps or repeats; `listMovementsAfter` returns oldest first and picks up a new movement after a remembered id; totals never add quote to coin; bad input is a `RangeError` and hostile text is only a parameter; deleting every movement and replaying the stored events rebuilds identical rows, and a second replay writes none; a replay over 1,200 stored events that mean nothing followed by 600 that do writes all 600.

Mutations, each caught: dropping the NAV-window check (8 failures), stopping the backfill at a page with nothing to write (1), removing the live `recordMovement` call (10), pointing the DAO insert at a missing table (4), passing `qPrice` through a JavaScript number (2). One real defect was found by the tests while writing them: `ORDER BY id` resolved to the text output alias `id::text`, which sorted `10` before `2`; it is now `ORDER BY m.id`.

## Not covered

- Not run on a cluster, and not against a standalone Postgres server: there is none on this machine and `DATABASE_URL` is unset. PGlite is a real Postgres engine, but a server-side difference is NOT VERIFIED.
- The two events have never been emitted by a deployed program. The encoders come from the generated client of the same IDL the program builds from, and the LiteSVM tests of W3D-X3 and W3D-B4 cover the instructions, but no on-chain log was decoded here.
- No API route reads any of the new functions yet (see below), so the settlement read still does not list a DAO or tranche, and F5 has no trigger fed by these rows.
- `TrancheReleased` carries no destination, so its movement has a null counterparty.
- Movement ids are in ingestion order, which is a creation order only while a single indexer process writes.
- The dr.ts class given to `alert_insider_balances` and `alert_movements` (`backup`, the conservative one) is my reading of their definitions, not of the code that owns them; the owner of ADR-0940 should confirm it.

## Changes needed outside this package

- `services/api`, `GET /v1/crosses/:address/settlement` (`routes/rules-read.ts`): add `...await settlementMarkets(d.db, a)` (fields `futarchyDaos` and `presales`) next to `venue`, and include both lists in the "no settlement adapter has opened a venue" test for `note`. `oc_get_settlement` then shows them with no MCP change.
- `services/api`, new routes over the read functions: `GET /v1/treasuries/:treasury/movements?kind=&direction=&asset=&teamOutflow=&counterparty=&minAmount=&sinceSlot=&before=&limit=` over `listTreasuryMovements`; `GET /v1/treasuries/:treasury/movements/totals?sinceSlot=` over `treasuryMovementTotals`. Map `RangeError` to 400. The alert builder for treasury movements should poll `listMovementsAfter(db, lastId, { teamOutflowOnly: true })` and start new subscribers at `latestMovementId`. When the movements route exists, add `oc_list_treasury_movements` to `services/mcp/src/tools.ts` (not added now: `tools-routes.test.ts` fails a tool whose route is absent).
- `pnpm-lock.yaml`: the indexer gained the devDependency `@electric-sql/pglite ^0.5.9` (already in the lockfile for `services/api`); `pnpm install` must refresh the importer entry. Locally the package resolves through a junction in the git-ignored `services/indexer/node_modules`.
- Documentation that lists MCP tools: `docs/agent-skill/opening-cross/SKILL.md` and `docs/api/W4A-new-programs.md` should name the two new drafts.
