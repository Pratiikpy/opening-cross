# W2C-S11: practice cross

Outcome: **BUILT**. Design: ADR-0410. Code: `apps/web/src/app/practice`, `components/portfolio/practice-page.tsx`, `lib/holder-practice.ts`.

A 60-second call with a simulated seller and nine simulated bidders drawn from a seeded generator, 1,000 play money, the same clearing rule as a real cross (`components/cross/clearing.ts`), the real book chart, a banner that nothing touches a wallet or the chain, a debrief with three questions answered from the run, and a reset with new bidders.

Tests (`apps/web/test/holder-practice.test.ts`, 8): the scenario is the same for the same seed; every simulated order is on the grid and inside the call; the book shows only what has arrived; for eight seeds the clearing price and matched amount equal the verifier's independent reference (`packages/verifier/src/reference.ts`) with the learner's order included; a filled buyer pays the clearing price never the limit and the rest is refunded; a bid below the price is not filled and refunded whole; a higher limit pays the same price.

Browser run (`holder-pages-flow.mjs`, a full 60-second call): banner shown; a price off the grid is refused with the step; an order larger than the play balance cannot be placed; the order is held in escrow and described; the debrief reported "filled for 120 of 120 tokens at 1.5, paying 180 play money. 6 play money came back."; the quiz marks a right and a wrong answer and explains from the run; reset returns to the start; axe clean; zero console errors. Screenshot read: `screens/w2c/practice-running-1440-light.png`.

Not covered: a phone-width run of the practice page in the flow script (it is part of the route audit, W2C-M10); a sell order in practice (only buying is practised); a replay of the same seed in the browser.
