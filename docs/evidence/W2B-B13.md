# B13 float and FDV guardrails, from the issuer wizard (2026-10-13)

Outcome: BUILT. The guardrails are enforced on chain through parameters the deployed `cross_core` already has (ADR-0351). A dedicated on-chain guard (`min_float_bps`, `max_fdv_x100`) is being added by the programs workstream and is not what runs on devnet.

## What was run

`apps/web/e2e/issuer-wizard.mjs`, a real browser (Chromium) against a local build of `apps/web` pointed at the live devnet API (`https://98-87-59-136.sslip.io`, through a forwarding harness that also serves the new issuer routes) and Solana devnet. A throwaway issuer wallet held the mint authority of a fresh 6-decimal token with 9,000 tokens already minted.

In the page, as a person would:

1. Listing type Ownership coin, format Open-book launch, supply step 1,000 tokens at 1.20.
2. Minimum float 5%. The page said a float of 5% needs at least 473.684211 tokens to trade, because 9,000 tokens already exist and a minting cross adds what it sells: m / (9,000 + m) >= 5% gives m >= 473.684211.
3. Highest fully diluted value 20,000 quote. The grid (1.00 to 2.95 in 40 levels) failed readiness, because 2.95 x (9,000 + 1,000) = 29,500. Pressing "Shorten the grid to 21 levels" made it pass: the top is 2.00, and 2.00 x 10,000 = 20,000.
4. Connected the wallet, every readiness item passed, pressed Create.

## What the chain holds

Cross `F3SsSoCb3s8p3AsX1bQrHR3vi4Chs765qE9kJq3xrntu`, read from the account with the SDK decoder (`getCrossDecoder` in `@opening-cross/sdk`):

```
minMatched 473684211   maxImbalanceBps None   ticks 21   minPrice 1000000   tick 50000
```

`minMatched` is exactly the 5% float translation, and `ticks` is the shortened grid. The mint authority of the token moved to the cross in the same transaction (checked by the script from the mint account).

## Arithmetic checks

`apps/web/test/issuer-guards.test.ts` and `issuer-wizard.test.ts`: the minimum is minimal (one atom less gives a float under the target) for four supplies and floats; the value ceiling is tight (one price unit more exceeds it); and the simulated cross prints at the float and not one atom below it (`BelowMinimumVolume`), in both mint and escrow modes.

## Not covered

- On-chain enforcement by a dedicated float or value guard (needs the programs workstream's change on devnet).
- A supply that changes between reading the token and creating the cross (the wizard re-reads on demand, not at the moment of signing).
- Insider-excluded allocations (VM7), which would change the float.
- No default float or value ceiling is proposed: the page applies the issuer's own limits only.
