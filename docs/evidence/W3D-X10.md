# W3D-X10: adversarial bounty (`cross_bounty`), proved on LiteSVM

Status 2026-10-14: **program, client and tests built; proved on LiteSVM, with the invariants checked against 300 randomized honest crosses; not deployed (H27); the mainnet pool is a human step.** Not audited. ADR-0654. Row X10.

## What was built

A new program `BSXaBkmhyypBNp5nfwb4GHAL7uDDLVR8Tr3UyHJKsWMz` (277,992 bytes), 5 instructions (`create_bounty`, `fund`, `claim_invariant`, `award`, `withdraw`), 5 events, 13 errors, and the client `@opening-cross/cross-bounty-client`.

The pool is committed until an expiry at least thirty days away. It pays automatically (once per invariant) to whoever shows a cross account that breaks one of eleven invariants, and the arbiter named at creation can award it for what the chain cannot check; the sponsor can withdraw only after the expiry.

## Tests

- `tests/core/test/bounty.test.ts`: **317 passed** with `BOUNTY_RUNS=300` (the default is 12). 300 randomized honest crosses (open and sealed, escrow and mint mode, random fees and reference prices, orders not revealed) are probed with all 11 invariants at six stages (empty, live with orders, cleared or not printed, partly claimed, fully claimed, finalized): **about 19,800 probes, none fired** (`NoViolation` each time), and the pool stayed untouched. Each invariant pays on exactly the state it names (the account is rewritten in LiteSVM, still owned by `cross_core`), pays once, and the same break on another cross is refused (`AlreadyPaid`); an uncovered invariant, an unknown one, the bounty's own account and a cross-shaped copy owned by another program pay nothing; a pool smaller than the reward pays what it holds and then refuses (`PoolEmpty`); a bounty under thirty days is refused; the sponsor cannot withdraw one second before the expiry and nobody else can ever; only the arbiter awards, only before the expiry, capped by the pool; anyone can fund.
- `cargo test -p cross_bounty`: 4 passed (a blank cross breaks nothing; each invariant fires on exactly its shape; the grid check is exact).
- A false positive found by this method and fixed: the first form of invariant 7 ("buyers paid in at least what sellers received") fired in 8 of 300 honest runs (rationing leaves base the sellers delivered and are paid for). It is now the exact bound the rounding implies, `seller_paid <= buyer_paid + (sold - bought) x P / scale`, and the old form is kept as a mutation the honest runs catch. 279 cleared crosses were also tabulated: `bought <= sold` and `bought <= matched` held in all, `sold <= matched` did not (24 cases of dust), `buyer_paid >= seller_paid` did not (11 cases).
- Mutation checks: double payment allowed -> every invariant test fails; early withdrawal allowed -> 1 fails; arbiter check removed -> 1 fails; the cross owner check removed -> 1 fails; the old invariant 7 -> 8 honest runs fail; payouts after the expiry -> 1 fails.
- `cargo fmt --check`, `cargo clippy -D warnings`: clean.

## What the app layers must add

SDK: builders for the five instructions. Indexer: project `BountyCreated`, `BountyFunded`, `InvariantPaid`, `Awarded`, `BountyWithdrawn` and the `Bounty` account (paid mask, awarded total). API: a bounty read and a "report an invariant break" helper that finds a cross whose account violates one (the same predicate as `violates`, available in the verifier package as a pure function). Web: a public bounty page (pool, expiry, rewards, what was paid). Keeper or monitor: run the predicates over every live cross and alert before anyone else claims. Diagnose: add the 13 errors.
