# W2D-X13: Alpha Vault entry, Met Lock and batch-opened pools, proved on LiteSVM

Status: **proved on LiteSVM against the real binaries; devnet proof pending funding.** ADR-0483, ADR-0484. Tests: `settle-batch.test.ts` (4), `settle-alphavault.test.ts` (1), `settle-metlock.test.ts` (2), `packages/adapters/test/metlock.test.ts` (pure, 2).

- Batch pools: `seed_damm_v2_batched` opens a compounding DAMM v2 pool with a decaying fee and a start 600 s away; a swap before the start is refused by DAMM v2 itself (`PoolDisabled`); after the start the swap pays the opening fee (3%) and a later swap the settled fee (0.3%): 11,616,765 vs 11,892,834 quote atoms for the same 10,000,000 base. The program refuses a start inside the window (`BatchActivation`), a fee that never steps (`BatchFeeNotDecaying`), a non-compounding pool (`BatchNotCompounding`) and a window outside 30 s to 7 days (`BatchWindow`), checked by tampering with the instruction bytes. `open_dlmm_pair_batched` records the start in the DLMM pair and refuses the same departures.
- Alpha Vault: pro-rata vault bound to the batch pool; 9 and 3 deposited against a cap of 8; a public swap is refused before the start, the vault's fill succeeds, a second fill is refused; claims 3:1 to within rounding; refunds exactly 3 and 1; the vault ends empty.
- Met Lock: the escrow holds the full schedule; claims at six instants equal the adapter's `metLockVested` exactly; a claim before the cliff moves nothing; a claim signed by another wallet moves nothing.

Not covered: the DLMM Alpha Vault fill, FCFS mode (builder untested), merkle whitelist, escrow cancellation, devnet.
