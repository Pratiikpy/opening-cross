## R11: the operations console in the web app

Built: `/ops` (`apps/web/src/app/ops`, `apps/web/src/components/ops`): sign-in, listings (queue, open a review, evidence per source, decide, cross lookup), incidents (open, acknowledge, resolve), cases (open, notes, close), audit log (newest first, paged, verify, signed head with download). The web app's `/ops/api` route is the only path from the browser to `services/ops`. Two service additions: `GET /v1/ops/listings/:id` (the second reviewer reads the evidence the first gathered; before this they could not) with `evidence_failed` in the queue, and `GET /v1/ops/log?order=desc&before=`.

Proved:
- `services/ops` against Postgres 17 in Docker: 15 of 15 (13 before; 2 new: evidence readable by the second reviewer and the failed sources in the queue; the log read newest first in joining pages with five refused forms of the query). `tsc` clean.
- `apps/web` ops unit tests: 22 of 22 (proxy path rules: the webhook, `..`, encoded separators, control characters, a smuggled host; header forwarding drops the cookie; the real route handler run against a real HTTP server: query and body forwarded, the service's own status passed through, a redirect not followed, a body over 64 KB refused before forwarding, a 502 when the service is down; the client; every form check). `next`'s `tsc --noEmit` has no error in an ops file (7 errors exist in `src/app/gates`, not mine).
- Browser, one isolated context per person (viewer, two reviewers, admin, a stranger), real service, real Postgres, the real API gathering real evidence for Circle's devnet USDC mint: 104 of 104 checks. Outcomes read back from the service afterwards, not from the page: a wrong token refused and not stored; the webhook unreachable through the web app even with the right secret; other methods 405; viewer offered no forms; the opener told someone else decides and the service itself refusing a self-decision (403); the second reviewer reading the same evidence including the source that really failed (the API's holders route returned HTTP 500); approval blocked client-side until the failed source is acknowledged and the acknowledgement in the log under bob's name; incident from the monitor's webhook, acknowledged by a reviewer, the resolve button absent for a reviewer and the resolution recorded under the admin; a case with two reviewers' notes in order, the note text absent from the audit log, close only by the admin, a closed case offering no note; chain verify agreeing with the service (entry count); the signed head downloaded and equal to the service's; **a row edited directly in the database found by the page at the right entry ("its content does not match its hash (it was edited)"), the head refused while broken, the row restored and verification passing again**; session kept on reload, dropped on sign-out and for a revoked token; a cut connection shown as a message. Per page and theme: WCAG 2.2 AA (axe, `wcag22aa`) clean, no horizontal scroll, zero console errors, page errors, failed requests and HTTP errors (the deliberate refusals are named in the script).
- One defect found by looking at the first run, fixed: the evidence rows' status text is upper-cased by CSS, which only the test's string match noticed. No product defect surfaced beyond the missing read route above.

Not covered: real people and tokens (H34, none issued); a proxy that restricts `/ops` to an operator network (not configured or tested); login throttling (the service has none); Firefox and Safari; a screen reader run.

## L7/J4: the docs service

Found: a docs MCP already existed in `services/mcp` (stdio and local HTTP, BM25 over the repository's markdown, tested). The row's "No docs MCP" was out of date. Built `services/docs-mcp`, a hosted layer on it (ADR-0972): web pages for people (search; a rendered document or section), MCP over Streamable HTTP with two added tools (`oc_explain_error`, `oc_diagnose_failure`), a JSON API, `/llms.txt`, `/healthz`, a per-client limit, a body cap, a publish policy (runbooks and security notes off by default), CORS for reads.

Proved: 26 of 26 tests over the repository's real documents (about 360) (default policy: no runbook or security document in the index, and a read of one returns 404; paths outside the corpus including `.keys/...`, `../..`, `C:\...` all 404; 400s for every malformed query; a 300 KB MCP body 413; 429 with `Retry-After` and health not counted; markdown rendering escapes scripts and raw HTML, drops `javascript:` and `data:` links, resolves links to other documents and shifts section headings; the real server process over a socket with the MCP client: five read-only tools, a search, an explanation of an error from the hex a log prints, a diagnosis of a real log, typed errors for an unknown program and a bad code, a second client unaffected by the first, the kinds policy and the limit set by environment). Browser (`e2e/site.e2e.mjs`): 44 of 44 (WCAG 2.2 AA, no horizontal scroll, zero console errors, four themes and sizes). The browser run found two real defects, both fixed: a section page had no top-level heading (axe `page-has-heading-one`), then its first heading skipped a level (`heading-order`).

Not covered: a public deployment, TLS and the proxy route (the service is not in `deploy/Caddyfile`); semantic search (it is keyword ranking and will miss a question in none of the document's words); the licence of Meteora's captured documentation (NOT VERIFIED: only links and a per-error cell are used); the lockfile (the package is linked locally; `pnpm install` must add it).

## L5: version-matched docs in the diagnosis

Built (ADR-0973): `diagnose()` now returns `docs` for an error of Meteora DBC, DAMM v2, DLMM, Zap or Raydium CPMM: pages, the documentation's explanation, `raisedIn` where the documentation lists where an error is returned, a source permalink at a pinned commit, and `versions` (IDL, documentation changelog, source `Cargo.toml`, each compared with the IDL) with a note in words. Generated by `pnpm --filter @opening-cross/diagnose generate` from the local documentation capture and the cloned repositories; nothing typed by hand; every disagreement printed.

Proved: 45 of 45 (36 before, 9 new). Every source link is followed to its line at its commit (`git show <commit>:<file>`, 150+ lines, each containing the error's name); every documentation page is in the capture's URL list (8 pages); the documentation's words are attached only where the name and code equal the IDL's; for DBC all three releases agree (0.2.1); **for DAMM v2 the diagnosis says the documentation (0.2.4) and the source (0.2.4) are not the IDL's release (0.2.5)**; DLMM has the documentation and no source link; Raydium has the source link and no page; Opening Cross programs, Anchor framework errors and runtime errors have `docs: null`; an unlisted code still gets the pages and the note. Findings printed by the generator: Zap documentation lists 0.2.2 against IDL 0.2.0; Raydium's source has an error the IDL on file lacks (`LamportsCalculateError`, 6015). The same output is reachable through the docs service's `oc_explain_error`.

Not covered: that the commit read is the release the deployed program was built from; documentation for programs other than those five; a diagnosis against a live failed transaction of these programs in this change (the earlier mainnet check of the error tables, 69 of 69, is unchanged).

## Q2: Mollusk beyond admin, and Surfpool

Mollusk (`tests/mollusk`, WSL, nightly, 37 of 37 in four suites; the first suite's 11 unchanged):
- `idl_surface` (5): 12 programs, 169 IDL instructions. 327 discriminators equal Anchor's derivation (four `cross_gate` interface instructions follow their interface's, named); each of the 152 instructions the binaries route reaches its handler and refuses an empty call (compute units printed per program); an unknown discriminator, an account discriminator and 0, 1 and 7 bytes are refused as "no such instruction" (101); each binary refuses to run at any address but its IDL's (4100); names and error numbers unique. **Finding: `target/deploy/cross_gate.so` (built 2026-10-11) routes 17 of the IDL's 34 instructions**; the test pins the list and fails when the binary is rebuilt.
- `backing` (8): `cross_backing` with a real call into `cross_core` (protocol and halt state made by `cross_core`'s own instructions): terms and who may opt in, the attester and the chain clock, `check` halting through `set_halt` for missing, stale or short backing (17,634 compute units), refusing with `Backed` and changing nothing when fresh and covered, coverage and age exact at their edges, the live supply (one new atom un-covers), substituted accounts.
- `core_halt` (13): who may register a halt state and who may halt; the first reason standing; corporate actions; a Token-2022 pausable mint built byte for byte copied in by anyone (extension number 26 confirmed by the program halting on it); the oracle circuit breaker on hand-built Pyth updates (a 5.00% move not tripping, 5.0095% tripping, either direction, outside the window, across exponents, eight kinds of update refused, replay and older refused, an asset with no breaker refused).

Surfpool (`tests/surfpool`, surfpool 1.6.1 offline in WSL, real binaries written to their real addresses with `surfnet_writeProgram`, 16 of 16): the surfnet boots with `cross_core` and a protocol account; a mint-mode launch with an open book and a sealed escrow-mode cross driven through create, place, cancel, commit, reveal, clear, claim and finalize and compared with the independent reference (price, matched volume, every fill, every refund, the unrevealed order refunded in full, the mint authority revoked, the quote vault empty); the refusals between steps by number (off-grid 6005, order and cancel after the call 6007, claim and finalize before clearing 6022, clearing during the call or reveal window 6009, a reveal too early 6008, wrong salt and wrong price 6018, a second claim 3012); pause by the admin and not a stranger (6001, 6000 on create while paused); the fee cap (6004); all six `cross_calendar` instructions with the clock moved across the seven-day timelock, including ten seconds early (6004), apply by a stranger, cancel, and the admin handover (the old admin refused after). Observed, not assumed: an open-book cancel after the call is `NotInCallWindow`, not `CancelClosed`.

Not covered: no mutation test of the Mollusk or Surfpool suites; the order, clearing, claim and settlement instructions of `cross_core` in Mollusk (Surfpool covers them whole); `cross_gate` (stale binary); `cross_settle`, `treasury`, `cross_mandate`, `cross_conviction`, `cross_basket`, `cross_listing`, `cross_bounty`, `cross_graduate` beyond routing; settlement into Meteora and Raydium (not on an offline surfnet); the 65-session limit of `cross_calendar` (cannot be sent in a transaction); compute-unit budgets are printed, asserted only loosely.

## V-E (wasm): the v2 rules in WebAssembly, in a browser

Built (ADR-0974): `packages/clearing-wasm/rust` (own workspace, `clearing-core` by path) builds `clearing-v2.wasm` (36,836 bytes, `opt-level = "z"`, no `wasm-opt`): supply cap, minimum raise, float, valuation, price move, allocation classes, the class-1 lottery, insiders; where a guard stopped the print the result still gives `wouldClearAt`. `loadClearingV2` in `src/v2.ts`.

Proved: Rust 4 of 4. TypeScript 9 of 9 (2 before): **all 437 v2 vectors the program generated reproduced, fills, insider bounds and the stopped-at price included**, covering all seven no-print reasons; the 525 v1 vectors through the v2 module with no rules equal the expected and equal the v1 module's every field; a 2,000-call loop leaves the answer unchanged; refusals (zero price scale, over-allocated reserves, a class or insider flag on a sell, a class of 4, off-grid, bad reference, values that do not fit 64 bits or 16 bits) before anything is called. **Mutation check: four defects introduced into the Rust (insiders counted in the raise; the lottery start not reduced; the cap ignored; tickets numbered globally) were each caught; the lottery-start defect first survived and a test was added that now kills it.** Browser (`test/browser/run.mjs`, Chromium 153, two contexts, light desktop and dark phone): the page fetches both modules and the vectors and runs 525, 437 and 525 vectors in the page, all matching, zero console errors.

Not covered: Firefox (not installed); byte-reproducibility of the build on another machine; `crates/clearing-wasm` itself (outside this package; the cleaner end state is one module there); a web screen that uses the module (none exists in the app).
