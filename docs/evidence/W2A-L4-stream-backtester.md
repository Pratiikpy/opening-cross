# W2A-L4, X16: the typed gRPC stream and the history backtester, run on devnet data

Rows: L4 and X16 (public data stream and a backtester over indexed history). Date: 2026-10-13. Code: `services/stream` (gRPC server, client, CLI, `proto/opening_cross/v1/stream.proto`), `services/indexer/migrations/009_event_ingest_order.sql`, `packages/backtester` (engine, strategies, history loader, CLI). Tests: `services/stream` 13 (10 in memory over a real local socket, 3 against Postgres), `packages/backtester` 12. The existing WebSocket feed `/v1/stream` is unchanged.

## The stream

`opening_cross.v1.EventStream` has `Subscribe` (server-streaming; replays the log after a cursor and then follows it) and `Head`. Every one of the nine events `cross_core` emits is its own message (`CrossCreated`, `OrderCommitted`, `OrderCancelled`, `OrderRevealed`, `CrossCleared`, `OrderClaimed`, `BaseMintBound`, `CrossFinalized`, `PauseChanged`); amounts are `uint64` (the matched volume, which the program counts in 128 bits, is a decimal string); enum values carry their names from the generated client, so a variant the program adds appears under its name. A client keeps the cursor of the last event it handled and resumes from it. Positions come from migration 009: `events.ingest_id`, a total order in ingestion order (existing rows are numbered in `(slot, signature, seq)` order; the migration is idempotent and was tested against a table that already held events). The server filters by cross and by event name, sends a heartbeat first (with the head) and while quiet, honours write backpressure, disconnects a client that stops reading with `RESOURCE_EXHAUSTED` (tested with 20,000 events and a client that never reads), ends with `INTERNAL` naming the position if it meets an event it cannot convert instead of skipping it, and ends with `UNAVAILABLE` when the log cannot be read. An optional bearer token and TLS are configuration (`STREAM_TOKEN`, `STREAM_TLS_CERT`, `STREAM_TLS_KEY`).

Real data: the indexer's own ingestion path (`pollOnce` with the cross account as the address) read every transaction that touched the finished market-maker cross `DfggnrfMbn7J47R2HYuJ1enZYSMzHmsyPTgVzkgWpe9T` from devnet into a scratch Postgres (9 events), the server served that log, and a client subscribed. It received, in order: `CrossCreated` (kind reopen, escrow, open), three `OrderCommitted`, `CrossCleared` (printed, price 1550000, matched 100000000, rationed sell), three `OrderClaimed` (the ask: fill 100000000, quote out 155000000; the bid: fill 0, refund 396591625; the taker: fill 100000000) and `CrossFinalized` (proceeds 3000). The cleared event carries the same price and volume as the fairness proof and the chain (`W2A-X6-marketmaker.md`). Resuming after the fourth event returned exactly the five that follow it, and a filter on `OrderClaimed` and `CrossCleared` returned exactly those four.

## The backtester

`opening-cross-backtest --api <url> --strategy passive-buy|market-maker|last-second-bid` reads every settled cross from the public API (the fairness proof carries the grid, the guards, the merged book the program cleared and the program's own record; the cross detail adds kind, supply mode and fees), replays them in the order they closed, and re-clears each with the strategy's orders added, by the independent implementation of the clearing rule (`packages/verifier`, the one that checks every cross on chain) plus the two guards a book decides alone. Before any strategy is applied each cross is replayed as it was and compared with the program's record: on the live API's history **86 of 86 replayable crosses matched** (7 more settled crosses could not be replayed: they never had a base mint bound). That is the replay engine's own test against the chain, and it is reported with every run. The `market-maker` strategy imports `buildQuote` from `services/marketmaker`, so a backtest of it exercises the code that runs on devnet.

Live run: `opening-cross-backtest --api https://98-87-59-136.sslip.io --strategy market-maker`: it took part in 2 crosses (only pairs with an earlier print have a reference price, and most devnet test crosses use a fresh pair), sold 25,000,000 base atoms for 31,250,000 quote atoms net of fees, and made 2 crosses print that would not have (its two-sided orders met an otherwise one-sided book). No cross printed both with and without it, so no change of clearing price was measured. One cross in the real data (`DfggnrfM...`) is used as a test fixture: adding a 150-token bid at the top of its real book moves the clearing price to 1.60 and rations the buyers: the existing 100 gets 80 and the new 150 gets 120 of the 200 on offer.

## What it is not

It is a replay of devnet test traffic, not market data, and it says so. It does not model how other participants would have reacted to the strategy being there and it does not claim a profit: a closed history has prices that printed, not prices that came next. The Meteora idea it answers (an all-history backtester for bonding curves) would also need the history of Meteora pools, which this repository does not hold; this is a backtester for Opening Cross's own calls. Crosses with extended allocation rules, sealed crosses and crosses whose verdict rested on an oracle, a halt or a corporate action are skipped or labelled; they are not replayed as if the book decided them.

## Not covered

The stream was not run against the deployed database (the deployed stack does not run it until `deploy/docker-compose.yml` gains a `stream` service, listed in the report); TLS with a real certificate; many simultaneous subscribers; Rust or Python clients generated from the proto (the proto is the contract; no generated client other than the TypeScript one was run). The backtester has no database source (the API is the source).
